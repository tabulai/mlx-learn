# KNN: consistent 2× on the original 50,000 × 32 benchmark

The requested speed target is now met on the original short-warmup protocol.
Across two independent runs, all **54 operation–dataset medians** exceed
untouched default-thread sklearn by **2.10–3.02×**. All **108 chronological
half-sample medians** also exceed 2×; the minimum is 2.04×. These cover nine
search/inference operations, including fresh fit plus query, on three datasets.
The implementation is **1.40–1.56× faster than the immediately preceding version**
on these operations.

This is a measured median-latency result, not a guarantee for every call. Of 486
paired timed rounds, **455 (93.6%)** reached 2×; all samples and misses remain in
the raw reports. Fit alone is reported separately and remains slower than
sklearn, which has little work to do when fitting a brute-force index. The 2×
claim applies to the stated 50,000-row workload, not every shape in the full panel.

## Implemented changes

1. **Compact training storage with conservative bounds.** The index retains its
   original owned float32 data and lazily prepares a half-storage copy plus each
   row's measured squared quantization error. Explicit scalar float32 arithmetic
   computes lower bounds for candidate selection. The final distances still use
   the original coordinate order and compensated arithmetic.
2. **Packed candidate keys.** Each key combines a downward-rounded 24-bit ordered
   distance bound and an eight-bit position within a lane's scan. This reduces
   private selection state and comparisons. The launch geometry prevents position
   overflow, and the quantization always weakens the bound safely.
3. **Short local lists with a global omission bound.** A lane retains two real
   candidates and a bound on everything it dropped. Bound markers participate in
   the partition merge, so a global certificate can prove that discarded points
   cannot enter the top k. This avoids keeping k+4 candidates in every lane.
4. **Fused final processing.** One kernel merges candidates, recomputes their
   original float32 distances, checks the omission bounds and returns sorted
   neighbors. An uncertain query performs the complete original scan. Ties,
   self exclusion and overflow keep their previous semantics.
5. **Lazy independent host storage.** GPU fits immediately own their training
   data. The additional host copy is created only for radius queries, pickling or
   explicit `_fit_X` access. Mutating that host copy still cannot change resident
   search data. CPU fits and reuse of privately cast float64 inputs retain their
   previous behavior.

The device core remains independent of NumPy and sklearn. Preparation belongs to
one fitted index; query results and user input identities are never cached.
The new dispatch covers 16,384–2,097,152 training rows, batches of at least 64
queries, 16–32 features divisible by four, and up to eight neighbors. Other
shapes retain the existing paths. Native automatic query blocks are bounded at
1,024 rows; blocks shorter than 64 rows keep the direct scan. Explicit reference
blocking still selects the general tiled path.

The [numerical argument](knn-compact-certificate.md) derives the actual lower
bound and explains packed rounding, omitted candidates and exact fallback.
The implementation does not depend on unspecified SIMD matrix layout or
reduced-precision matrix multiplication. The earlier mlx-geospatial-inspired
streaming list merge remains part of the search infrastructure; these new
Euclidean bounds were derived for this implementation.

## Measurement protocol and comparison version

The target uses **50,000 training rows, 32 features, 256 query rows and k=5**.
It is not a 50,000-row self query. Dataset seeds are 51, 52 and 53; two query rows
are copied from training data to exercise zero-distance weighting. Inputs are
float32. Hardware: Apple M4 Max, 128 GiB memory; Python 3.13, MLX 0.32.2,
sklearn 1.9.0 and NumPy 2.5.2.

The previous implementation is frozen in
[`knn-pre-v3-2026-10-28.zip`](../benchmarks/reference/knn-pre-v3-2026-10-28.zip),
with 54 source files and a verified manifest. Current workers contain 55 source
files. Every final report's current hashes match the final source tree.

The unchanged benchmark runs isolated workers, three warmups and nine retained
calls per operation, interleaving variant order. It synchronizes GPU work and
includes public validation, transfers and output conversion. Fresh fit plus
query constructs a new model every time, including compact preparation.
Default sklearn keeps **16 OpenMP threads**; the single-thread comparator runs
in a different worker. Backend checks verify brute-force execution and the
actual model used for each operation. No power settings, priorities, thread-wait
policies or benchmark warmup rules were changed.

The native-resident column excludes the public NumPy boundary and uses already
uploaded inputs. It is an additional diagnostic, not the acceptance comparator.
Accuracy checks run outside timing: exact neighbor indices, distance
`atol=rtol=1e-6`, and matching classifier/regressor results at the established
benchmark tolerances. Prototype and production-kernel tests also require
bit-for-bit equality with the original compensated scan.

## Full eleven-shape benchmark panel

Every implemented operation is shown below, including slower and unchanged
shapes. The compact kernel is used by the 50,000-row case in this panel; other
cases retain their previous search kernels. Their measured differences can
include runtime variability and the lazy host-copy change, so gains on unchanged
search kernels should not be attributed to compact search.

The largest observed regression versus the immediate previous version was 1.46%
for fresh fit plus query on the 8-feature, k=32 batch (1.941 → 1.970 ms).
Current, previous and native-resident implementations passed every quality audit.
The full report's overall `quality_pass` remains false because both sklearn
comparators reproduce the existing 1,024-feature copied-row distance residual
of 2.47349e-6, exceeding the strict 1e-6 absolute zero-distance tolerance. Their
indices match. That comparator-only failure remains recorded; it was not hidden
by changing the tolerance.

## Other ideas tested

These exploratory results use separate probe conditions. Their raw samples,
rejected variants and source hashes are retained in the
[experiment archive](../benchmarks/results/knn-v3-experiments-2026-10-28.json).
They are not replacements for the public acceptance timings above.

| Experiment | Finding | Decision |
|---|---|---|
| Per-pair cheap screening before exact Kahan | SIMD divergence erased arithmetic savings; about 0.90–1.00 ms versus 0.62 ms in the probe | Rejected |
| Fused Gram selection with more partitions | About 0.59 versus 0.66 ms hot; inconsistent cold benefit | Rejected |
| Half-precision GEMM | Matrix materialization and uncertain-row work erased gains | Rejected |
| SIMD matrix scan | About 0.61 versus 0.65 ms hot; worse cold behavior and insufficient portable arithmetic/layout guarantees | Rejected |
| Per-lane overselect/refine/rescan | Added local state and refinement cost more than they saved | Rejected |
| 64–512 exact-scan partitions | Additional selection and merging erased most gains | Rejected |
| Adaptive exact lists with partition-local rescans | 408 correctness cases passed; at most a small hot gain, inconsistent cold results | Rejected |
| Half storage with measured errors and packed keys | Reduced memory and candidate state | Retained |
| Global omission bounds with two real candidates per lane | Removed most private-list state without losing exactness | Retained |
| Fused borrowed-input copy/finite check/compact preparation | 22 correctness checks passed; additional validation and synchronization prevented a consistent fresh-fit win | Rejected |

A standalone native Metal diagnostic measured command-buffer GPU time directly.
After one second idle, the first 20 calls had median GPU duration about 2.03 ms;
later 20-call windows were about 0.66–0.75 ms. The wall-time difference therefore
cannot be explained solely by MLX or Python dispatch. GPU clocks were not measured, so this
still does not identify a specific hardware power-management cause. These
observations motivated reducing the actual search work instead of extending
warmup or changing scheduling policies.

## Validation and practical limits

- **461 pytest tests passed**, including parity, float32 edge cases, native device
  APIs, compact-search integration, patching, sklearn compliance and the device
  logistic regression checks. The run produced 34 existing warnings.
- The independent compact suite contains 52 tests, including 3,652 individual
  lower-bound comparisons. Additional prototype/production sweeps passed 525
  adversarial configurations and 13,400 lower-bound comparisons. These are
  separate checks, not extra pytest test-count claims.
- Five 50,000 × 32 datasets (seeds 51, 52, 53, 77 and 99) matched the original
  scan bit for bit; all 256 query certificates passed on each dataset.
- Tests cover ties, many winners in one lane, self offsets, half and float32
  subnormals, overflow, large common offsets, mixed scales, sliced/unaligned
  inputs, packed position 255, query-block tails, refits, mutable input ownership,
  host-copy isolation and pickle/radius compatibility. Fresh-process tests block
  NumPy and sklearn imports from the device core.
- Ruff, repository compliance checks and `git diff --check` pass.

Difficult data can fail the compact certificate and invoke the complete exact
scan. That preserves results but can cost more than the ordinary direct path;
these measurements do not promise a 2× improvement for duplicate-heavy,
extreme-scale or arbitrary workloads. The general wider-feature Gram path keeps
its previously documented candidate-selection limitation. Fit-only medians on
the target were 0.472–0.496 ms versus sklearn's 0.362–0.392 ms.
